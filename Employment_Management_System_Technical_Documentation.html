03 Executive Summary (Simple Overview)

In Simple Words: The Employment Management System (EMS) is a web application that helps a company manage its employees. Instead of using paper files or Excel sheets, an HR manager can open a web browser, see all employees in a clean table, add a new employee, edit someone's salary or department, search by name, filter by department, or delete someone who left the company.

How It Is Built:

  • Frontend (What you see): A single webpage built using plain HTML, CSS, and JavaScript. It has a Dark mode and Light mode, a search bar, and 4 cards showing stats (Total employees, number of departments, total payroll, and average salary).
  • Backend (The brain): A Java program using Spring Boot. It receives requests from the webpage (like "save this employee") and runs the business logic.
  • Database (Where data lives): Can save data into MySQL (for permanent storage) or into H2 (a temporary memory database for fast testing).
  • Testing & Deployment: It has automated tests (MockMvc) to make sure every button works, and it is packed inside a Docker container so it can run on any computer or cloud server (Render).

04 Problem Statement (Why Do We Need This?)

In many small offices and colleges, employee records are kept in Excel files or on paper. This causes several big problems:

  1. Mistakes and Typos: In Excel, someone might type department as "IT", another person types "it", and another types "Information Tech". This makes searching very difficult.
  2. Accidental Overwrites: If two people open the same file, one person's changes can overwrite another person's changes.
  3. Difficult Search: As the company grows to 500 or 1,000 employees, finding someone or calculating department salary takes too much manual work.
  4. No REST API: Other software (like payroll systems or fingerprint attendance machines) cannot easily read data from a spreadsheet.

05 Why Did We Choose This Project?

We chose to build an Employment Management System because it is the classic real-world software engineering problem. Almost every company in the world needs employee management software (like Workday, BambooHR, or internal HR portals).

Building this project teaches all the core skills of a modern full-stack developer:

  • How to design clean database tables with primary keys.
  • How to write REST APIs following proper HTTP methods (POST, GET, PUT, DELETE).
  • How to connect Java to databases using Spring Data JPA without writing long SQL statements.
  • How to write clean JavaScript to talk to the backend using fetch().
  • How to write automated tests so you know your code works before showing it to anyone.
  • How to put everything in Docker and deploy it to the cloud.

Main Goals (Primary Objectives):

  • Provide full CRUD functionality (Create, Read, Update, Delete).
  • Allow instant filtering of employees by department (like showing only IT staff).
  • Provide a web dashboard with live statistics (Total employees, total salary bill, average salary).

13 System Architecture (The 4 Layers)

Our Java backend is organized into 4 clean layers. Each layer has one specific job:

  1. Controller Layer (EmployeeController.java):
    The front door. It receives the HTTP requests from the browser (e.g., POST /employees), converts the JSON into Java objects, and returns HTTP responses with status codes like 200 OK or 201 Created.
  2. Service Layer (EmployeeService.java):
    The brain. It contains the business rules. For example, when updating an employee, it checks if the employee actually exists; if not, it throws an error.
  3. Repository Layer (EmployeeRepository.java):
    The database helper. It extends JpaRepository. We don't even have to write SQL queries—Spring Data JPA writes them for us automatically!
  4. Entity Layer (Employee.java):
    The blueprint. A simple Java class that represents an employee row in the database table with fields: id, name, email, department, and salary.

14 Why Use a Layered Architecture?

Beginners often put all their code inside one big file or directly inside the Controller. Why didn't we do that?

  • Easy to Understand: If you have a bug with saving to the database, you look in the Repository. If you have a bug with webpage routing, you look in the Controller.
  • Easy to Test: We can test the Service layer without even starting a web server or database.
  • Easy to Change: If tomorrow we want to switch from MySQL to Oracle or MongoDB, we only change the database layer—the Controller and frontend code don't need any changes!

15 Complete Request Lifecycle (Step-by-Step)

What happens when you click "Save Employee" on the webpage? Let's trace it step by step:

  1. Step 1 (Browser): You click "Save". JavaScript in app.js reads the form values (Name, Email, Dept, Salary) and puts them into a JSON package.
  2. Step 2 (Network): JavaScript sends an HTTP POST request to http://localhost:8080/employees.
  3. Step 3 (Controller): Spring Boot's EmployeeController catches this request. Jackson library turns the JSON text into a Java Employee object.
  4. Step 4 (Service): Controller passes the employee to EmployeeService.saveEmployee().
  5. Step 5 (Repository & Hibernate): Service calls EmployeeRepository.save(). Hibernate generates the SQL statement: INSERT INTO employees (name, email, department, salary) VALUES (?, ?, ?, ?).
  6. Step 6 (Database): MySQL or H2 executes the insert and gives the new employee an id (like ID 1).
  7. Step 7 (Response): The controller sends back the saved employee in JSON format with status code 201 Created.
  8. Step 8 (Screen Update): JavaScript gets the response, shows a green notification ("Employee saved successfully!"), closes the popup window, and adds the new row to the table.

17 Why Java?

Why did we choose Java instead of Python or Node.js?

  • Strong Type Checking: In Java, if a salary is a Double or an ID is a Long, the compiler makes sure you don't accidentally put text in it. This prevents many bugs before the code even runs.
  • Industry Standard for Enterprise: Most banks, colleges, and large companies use Java for their core business software because it is very fast, reliable, and secure.
  • Great Ecosystem: Spring Boot and Hibernate are mature tools that have been tested and improved for over 20 years.

18 Why Java 17 LTS? (And what about Java 23?)

The simple fact: Our pom.xml file specifies <java.version>17</java.version>.

  • What is LTS? Java 17 is an LTS (Long Term Support) release. That means Oracle and the open-source community support and patch it for many years. It is rock-solid and stable.
  • Minimum for Spring Boot 3: Spring Boot 3 requires Java 17 as the minimum version. You cannot run Spring Boot 3 on old Java 8 or Java 11.
  • What if you have Java 23? Java 23 is a newer version. If you have Java 23 installed on your laptop, the project will still run fine! But keeping Java 17 in pom.xml guarantees that anyone with Java 17 or higher can run the project without errors.

19 Why Spring Boot?

Before Spring Boot, building a Java web app was painful: you had to install a separate Apache Tomcat server, write hundreds of lines of XML configuration files, and manage dozens of jar files by hand.

Spring Boot fixes this by:

  • Built-in Tomcat: Tomcat is embedded inside the app. You just run java -jar app.jar and the web server starts automatically on port 8080!
  • Starter Packages: Adding one line spring-boot-starter-web automatically gives you everything you need for REST APIs and JSON parsing.
  • Automatic Configuration: Spring Boot looks at your dependencies and automatically configures database connections and templates for you.

20 Why Spring Boot 3.3.3?

Line 8 of pom.xml confirms version 3.3.3. We use this version because:

  • It uses the new jakarta.persistence namespace (the modern standard for Java persistence).
  • It includes the latest security patches and bug fixes.
  • It is fully compatible with Hibernate 6.5 and MySQL 8.0.

21 Why Spring Data JPA?

Without Spring Data JPA (using old JDBC), writing an "Employee lookup by ID" takes 20 to 30 lines of code: opening connections, writing SELECT * FROM employees WHERE id = ?, reading row columns, and closing connections.

With Spring Data JPA, all you write in EmployeeRepository.java is:

public interface EmployeeRepository extends JpaRepository<Employee, Long> {
    // That is it! Spring gives you:
    // .findAll(), .findById(), .save(), .deleteById() automatically!
}

This saves hours of boring repetitive typing and prevents typos in SQL statements.

22 Why Hibernate? (And how is it different from JPA?)

Important Viva Question: JPA vs Hibernate
JPA (Jakarta Persistence API) is just a set of rules and interfaces (like an official rulebook).
Hibernate is the actual engine that follows those rules and does the hard work of writing SQL and talking to the database.

Why Hibernate is useful:

  • Automatic Table Creation: With hibernate.ddl-auto=update, Hibernate checks your Java Employee class and automatically creates or updates the employees table in MySQL for you!
  • Automatic Updates: When you change an employee's salary in Java, Hibernate notices the change and automatically runs an SQL UPDATE statement.

23 Why MySQL?

MySQL is the world's most popular open-source relational database. For employee records, MySQL is perfect because:

  • Employee data is structured into neat rows and columns (ID, Name, Email, Department, Salary).
  • It supports transactions (ACID properties), meaning records won't get corrupted if the power goes out.
  • It is permanently saved on the hard drive.

24 Why H2 In-Memory Database?

H2 is a super-fast database that runs completely inside the computer's RAM memory without needing any installation.

Why is H2 awesome in this project?

  • Instant Setup for Friends/Teachers: If you give this project to a classmate or teacher who doesn't have MySQL installed, they can just run the H2 command and the app works immediately!
  • Fast Testing: Our automated tests use H2. The tests start with a clean empty database, test all features, and erase everything in 3 seconds.

25 Why Dual Database Support? (MySQL + H2)

Our project supports both databases using Spring Profiles:

  • Default Profile (MySQL): Uses application.properties to connect to MySQL on port 3306 for permanent real-world storage.
  • H2 Profile: Uses application-h2.properties to run with zero installation.

You can switch between them just by adding -Dspring-boot.run.profiles=h2 to your command. You don't have to touch a single line of Java code!

26 Why Maven & The Maven Wrapper?

Maven is our build tool. It reads pom.xml and downloads all the Spring Boot, MySQL, and Hibernate libraries automatically from the internet.

What is mvnw (Maven Wrapper)?

  • Normally, to build a Java project, you must install Maven on your laptop and set up environment variables.
  • With the Maven Wrapper files (mvnw.cmd on Windows, mvnw on Linux/Mac), you don't need to install Maven at all! The script downloads the correct Maven version automatically.

27 Why Vanilla HTML, CSS, and JavaScript? (No React)

Why didn't we use React, Angular, or Vue for the frontend?

  • No Extra Tooling: React requires installing Node.js, npm, running npm install (which downloads 300MB of dependencies), and running a separate server.
  • Packed Inside Java JAR: Plain HTML, CSS, and JS files sit inside src/main/resources/static/. When you build the Java project, the frontend gets packed directly inside the app.jar file! One single file contains both the backend and frontend.
  • Super Fast: The webpage opens instantly without waiting for a heavy JavaScript framework to boot up.

30 Dark and Light Mode (How It Works)

You can toggle between Dark mode and Light mode using the button in the top-right corner. Here is the simple 3-step mechanism:

  1. When clicked, JavaScript toggles the attribute data-theme="light" or data-theme="dark" on the root <html> tag.
  2. In styles.css, CSS variables (like --bg-primary and --text-primary) change their color values automatically.

33 JPA Annotations (What Do Those @ Symbols Mean?)

In our Java code, you will see several annotations starting with @. Here is what each one does:

  • @Entity: Tells Spring and Hibernate: "This Java class represents a table in the database."
  • @Table(name = "employees"): Tells Hibernate to name the database table employees.
  • @Id: Marks the id variable as the Primary Key of the table.
  • @GeneratedValue(strategy = GenerationType.IDENTITY): Tells the database to automatically increment the ID (1, 2, 3...) when a new employee is added.
  • @Repository: Marks EmployeeRepository as a database access interface.
  • @Service: Marks EmployeeService as a business logic service component.
  • @RestController: Tells Spring: "This class receives web requests and sends back data as JSON."
  • @CrossOrigin(origins = "*"): Allows web browsers running on any address to call our APIs without being blocked by CORS security.

36 HTTP Status Codes (Quick Revision)

  • 200 OK: Success! Used when fetching (GET), updating (PUT), or deleting (DELETE) works properly.
  • 201 Created: Used specifically when a new employee is created and added to the database.
  • 404 Not Found: Used when you ask for an employee ID that does not exist in the database (like searching ID 999).
  • 500 Internal Server Error: Means the server crashed (e.g., database connection was lost).

37 How Department Filtering Works

In EmployeeRepository.java, we wrote one simple line:

List<Employee> findByDepartmentIgnoreCase(String department);

How does this work without writing SQL?

  • Spring Data JPA reads the method name. It sees findBy + Department + IgnoreCase.
  • It automatically creates this SQL query behind the scenes: SELECT * FROM employees WHERE UPPER(department) = UPPER('IT');
  • The IgnoreCase part means it doesn't matter if you type "it", "IT", or "It"—it will find all employees in that department!

38 How Search Works (Client-Side Search)

When you type in the search bar on the webpage, how does it find employees so fast?

  • When the webpage first loads, JavaScript downloads all employees and keeps them in an array called allEmployees in memory.
  • When you type in #searchInput, JavaScript's filterAndRender() checks the query against 4 fields: 
    emp.name.toLowerCase().includes(query) ||
emp.email.toLowerCase().includes(query) ||
emp.department.toLowerCase().includes(query) ||
emp.id.toString().includes(query)
  • Because this filtering happens right inside your browser's memory, the search results update instantly with zero delay!

39 How Dashboard Statistics Are Calculated

The 4 cards at the top of the webpage are calculated by updateStats() in app.js:

  1. Total Employees: employees.length (e.g., 5).
  2. Active Departments: Uses a JavaScript Set to count only unique departments: new Set(employees.map(e => e.department)).size.
  3. Total Payroll: Uses JavaScript .reduce() to add up all salaries: employees.reduce((sum, e) => sum + (e.salary || 0), 0).
  4. Average Salary: Divides total payroll by total employee count: Math.round(totalPayroll / totalCount).

40 Testing Architecture (How We Test)

We test our application using Spring Boot Test and MockMvc in EmployeeControllerTest.java.

  • Before each test runs, employeeRepository.deleteAll() clears the database so every test starts fresh and clean.
  • The tests run against an isolated in-memory test database (jdbc:h2:mem:testdb) defined in application-test.properties. This ensures testing never touches or deletes real data.

42 Why MockMvc?

Normally, to test a website, you have to start the server, open a browser, click buttons, and check if it worked. This is slow and tedious.

MockMvc allows Java to pretend it is a web browser. It sends fake HTTP requests directly to the controller inside memory. It tests URL paths, status codes, and JSON responses in less than 3 seconds!

46 Dockerfile Explained (Line by Line)

A Dockerfile is a recipe that builds a container image for our project. Here is our Dockerfile:

# Stage 1: Build the JAR file
FROM maven:3.9.9-eclipse-temurin-17-alpine AS build
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline -B
COPY src src
RUN mvn clean package -DskipTests

# Stage 2: Create the small runtime image
FROM eclipse-temurin:17-jre-alpine
WORKDIR /app
COPY --from=build /app/target/employee-management-0.0.1-SNAPSHOT.jar app.jar
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar", "--spring.profiles.active=h2"]

47 Why Use a Multi-Stage Docker Build?

Stage 1 vs Stage 2 in Docker

[ Stage 1: Heavy Build Image (~850 MB) ]
Has Java Compiler, Maven, Source Code → Compiles app.jar → Discarded!
↓ Only app.jar is copied over
[ Stage 2: Clean Lightweight JRE Image (~180 MB) ]
Has ONLY the lightweight JRE and app.jar → Deployed to Cloud!

  • Saves 75% Disk Space: Our final container image is only around 180 MB instead of almost 1 GB!
  • More Secure: The final container does not have compilers, build tools, or source code inside it. Attackers cannot compile anything if they break in.

48 Docker Compose (Running App + MySQL Together)

docker-compose.yml lets you start both the Spring Boot app and a MySQL database with a single command: docker compose up -d.

  • Service 1 (mysqldb): Runs official MySQL 8.0 on port 3306. Saves database files permanently inside a volume named db_data.
  • Service 2 (app): Builds our Spring Boot app from the Dockerfile, exposes port 8080, and connects to the MySQL container over an internal Docker network.

66 "Why This and Not That" (Common Viva Comparisons)

1. Spring Data JPA vs Plain JDBC:
Plain JDBC requires writing 30 lines of code just to read one employee by ID. Spring Data JPA gives you findById() in a single line. It saves time and prevents SQL typos.

2. Vanilla JavaScript vs React:
React is great for huge apps like Facebook, but for an employee dashboard it introduces 300MB of dependencies and complex build scripts. Plain HTML/CSS/JS is fast, lightweight, and packs right inside the Spring Boot JAR file.

3. H2 vs MySQL for Testing:
Testing against MySQL requires setting up passwords and cleaning up rows afterwards. H2 runs in memory, runs tests in 3 seconds, and deletes everything automatically when tests finish.

72 Technical Interview Q&A (Memorize These!)

Q1: What does @RestController do in Spring Boot?
A: It is a combination of @Controller and @ResponseBody. It tells Spring that this class handles web requests and converts the returned Java objects directly into JSON.

Q2: What is the difference between @GetMapping and @PostMapping?
A: @GetMapping is used to fetch/read data without changing the server state. @PostMapping is used to send new data in the request body to create a new record in the database.

Q3: How does Spring Data JPA create queries from method names?
A: It reads method name keywords like findByDepartmentIgnoreCase. It parses findBy (SELECT), Department (the column), and IgnoreCase (UPPER() comparison) and generates the SQL automatically.

Q4: Why do we use Constructor Injection instead of @Autowired on fields?
A: Constructor injection makes variables final (immutable), guarantees all required dependencies are provided, and makes writing unit tests much easier without needing reflection.

73 Viva / Project Defense Questions

Q1: Why did you use two databases (MySQL and H2)?
A: MySQL is for permanent, real-world storage. H2 runs in memory with zero installation, which allows teachers, reviewers, or automated test runners to execute the project instantly without setting up a MySQL server.

Q2: What happens if I try to delete an employee ID that doesn't exist?
A: EmployeeService checks existsById(id). If false, it throws a RuntimeException. The controller catches this and returns HTTP status 404 Not Found with JSON {"message": "Employee not found with ID: X"}.

Q3: Why did you not use React for the frontend?
A: Using plain HTML, CSS, and JavaScript allows us to package the frontend right inside the Spring Boot JAR file. The entire app (frontend + backend) runs as a single self-contained JAR file under 50 MB with zero Node.js dependencies.
